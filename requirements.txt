# StockAI requirements — FIX-42 (M-2), verified against PyPI on 2026-10-01
#
# Rule used for every pin below: the version must ship a BINARY WHEEL for
# cp312, cp313 AND cp314 (or be a pure-python `py3-none-any` wheel), so
# `pip install -r requirements.txt` never compiles C from source.
# Checked with tools/build_requirements_lock.py -> requirements.lock.json
# and asserted by tools/verify_dependency_pins.py.
#
# WHY the old pins failed (measured, not guessed):
#   numpy==1.26.4      -> cp312 wheels only. On 3.13/3.14 pip falls back to the
#                         sdist and compiles (~3 min, needs a C toolchain).
#   pandas==2.2.3      -> cp312/cp313 only, no cp314 wheel.
#   scikit-learn==1.5.2-> cp312/cp313 only, no cp314 wheel.
#   yfinance==0.2.44   -> installs fine (pure python) but is DEAD against
#                         Yahoo's current API: yf.download("RELIANCE.NS",
#                         period="6mo") returned 0 rows with
#                         "JSONDecodeError: Expecting value: line 1 column 1".
#                         That is what made /api/stock answer
#                         "All 3 engines failed". 1.7.0 returns 130 rows.
#   xgboost            -> the audit's "no cp313 wheels" note was misleading:
#                         xgboost ships `py3-none-win_amd64` / `py3-none-
#                         manylinux*` wheels, i.e. no CPython-ABI constraint and
#                         nothing to compile. 2.1.4 fits + predicts fine.
#   tvdatafeed         -> still NOT on PyPI; the module ships as
#                         `tradingview-datafeed` (or from GitHub:
#                         pip install git+https://github.com/rongardF/tvdatafeed.git)
